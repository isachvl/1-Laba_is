# Прогноз до измерений

Профиль CPU: Ryzen 7 3700X, 8 физических ядер, 16 ГБ RAM, llama.cpp,
Qwen3-4B-Instruct-2507 Q4_K_M. GPU не используется (-ngl 0).

1. TTFT растёт примерно линейно на коротких входах, на длинных возможен
сверхлинейный рост из-за внимания и обращений к KV-кешу.
2. Весам FP16 требуется около 8 ГБ; Q4_K_M - около 2.5 ГБ (точный размер
сохраняется в паспорте). При условных 25-40 ГБ/с эффективной пропускной
способности RAM нижняя оценка чтения весов - 63-100 мс/токен. Это прогноз,
а не измеренная пропускная способность RAM. Реальный TPOT ожидается
около 0.1-0.25 с: есть распаковка весов, KV-кеш и накладные расходы.
Оценка 27 мс для T4 FP16 из методички не является границей этого CPU.
3. До опытов фиксируются пределы CPU: p90 TTFT <= 30 с и медиана TPOT
<= 250 мс. Это компромисс для локального учебного ассистента на CPU;
для комфортного промышленного диалога задержка 30 с слишком велика.
Ожидается прохождение при c=1 и нарушение одного из пределов при c=4.
Goodput: число запросов с индивидуальными TTFT <= 30 с и TPOT <= 250 мс,
делённое на полное время уровня; ошибки не считаются успешными.
4. При уменьшении общего контекста llama.cpp с 16384 до 8192 ожидаются
вдвое меньший KV-буфер (2304 -> 1152 МиБ) и лимит слота 4096 -> 2048
при четырёх слотах. Запрос 1024+128 всё ещё помещается в слот; рост или
падение допустимой нагрузки из этого автоматически не следует.

Файл сохраняется вместе с каждым запуском; фактические выводы - в отчёте.

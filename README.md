# Лабораторная работа №1

Рабочая папка: `D:\project\python\lab1`. Отдельное Python-окружение: `.venv`.
Старая работа из указанного GitHub находится рядом в `..\lab0` и не изменена.
Выбран CPU-профиль **из задания**: Qwen3-4B-Instruct-2507 Q4_K_M,
llama.cpp, контекст 16384, 1 слот для опытов 1-2 и 4 для нагрузки.
RTX 3060 намеренно не задействована: этот запуск соответствует CPU-сетке задания.

## Что открыть и сдать

- `report/report.pdf` - отчёт на 4 страницы, три графика и таблица нагрузки.
- `report/passport.md` - модель, ревизия, SHA-256, железо, команды и выдержки журналов.
- `report/defense.md` - сценарий показа и ответы на все 7 вопросов.
- `endpoint.yaml` - адрес, имя модели, параметры для следующих лабораторных.
- `client.py`, `prompts.py`, `experiment.py`, `results.py`, `analyze.py`, конфигурация.
- `data/pride_and_prejudice.txt` и `data/manifest.json` - текст и хеш.
- Папка запуска из `latest_run.txt`: JSONL, проверки, прогревы, журналы, таблицы и графики.
- `mlflow.db` и `mlruns` - сохранённые эксперименты и артефакты MLflow.

В `runs` могут остаться диагностические неуспешные запуски. Для сдачи используйте
завершённый запуск из `latest_run.txt`; его `metadata.json` должен иметь `completed`.
Вес модели и `.venv` нужны для запуска на этом компьютере, обычно их не сдают.

## Быстрая демонстрация (без повторения длительных опытов)

Откройте PowerShell. Первая консоль:

```powershell
cd D:\project\python\lab1
powershell -ExecutionPolicy Bypass -File .\start_server.ps1
```

Подождите сообщения, что сервер слушает 127.0.0.1:8080. Во второй консоли:

```powershell
cd D:\project\python\lab1
.\.venv\Scripts\python.exe demo.py
```

Будут показаны реальный ответ модели, 1024 входных и 64 выходных токена,
TTFT, TPOT и полное время. На CPU это занимает некоторое время.
Сервер работает только на этом компьютере; после демонстрации остановите Ctrl+C.
Для вопросов модели можно также открыть http://127.0.0.1:8080 в браузере.

## Повторить всё

Сначала остановите отдельно запущенный сервер (Ctrl+C): порт 8080 должен быть свободен.
Закройте тяжёлые приложения, отключите переход компьютера в сон на время опыта.

```powershell
cd D:\project\python\lab1
powershell -ExecutionPolicy Bypass -File .\run_all.ps1
```

Сценарий сам запускает/останавливает только свои экземпляры llama.cpp, делает
прогревы, проверки, три опыта и проверку половинного контекста из вопроса 7.
Каждый прогон сохраняется в новой папке. Отчёт пересобирается по последнему прогону.
Полный CPU-прогон значительно дольше демонстрации: десятки минут или больше,
в зависимости от загрузки компьютера. Не останавливайте его посреди серии.

Чтобы заново построить графики/отчёт по уже готовым данным:

```powershell
.\.venv\Scripts\python.exe analyze.py
.\.venv\Scripts\python.exe make_report.py
```

## Устройство кода и связь с ЛР0

Из исходного проекта перенесена организация: `Experiment` читает YAML,
создаёт папку запуска и метаданные, `Results` сохраняет записи, MLflow принимает
параметры/метрики/артефакты. Классификатор и обучение ЛР0 для этой задачи не нужны.
Клиент использует `AsyncOpenAI` с потоковой выдачей и без скрытых повторных запросов.
Токенизатор берётся из загруженного GGUF через API llama.cpp.
Перед каждой серией один прогрев, не включённый в `results.jsonl`.
Метрики вычисляются из исходных JSONL, ошибки и неверные длины останавливают опыт.
